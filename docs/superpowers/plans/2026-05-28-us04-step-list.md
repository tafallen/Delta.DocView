# Delta.DocView — US-04 Step List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Render the filtered step library as a scrollable list — grouped by domain when no domain filter is active, flat when one is — with type chips, parameter pills, query highlighting, per-row star + add buttons, and click-to-select that drives a new `SelectionState` service. Plugs `FilterEngine.Apply` into the visible UI for the first time.

**Architecture:**

- A new `Scoped SelectionState` holds the current `Step?` selection plus a `Changed` event. Set by `StepList` on row click; the detail panel (US-06) will subscribe later. Decoupling now means US-06 doesn't have to thread an `EventCallback` through `MainLayout`.
- `StepList` subscribes to `FilterState.Changed`, `IFavouritesStore.Changed`, and `ClientStepLibraryStore` population (already complete by the time `StepList` first renders, but the subscription set mirrors the engine inputs). It calls `FilterEngine.Apply(store.Steps, state, favs)` on every render. Results cached on `Filtered` field, recomputed in `OnParametersSet`/event handler.
- Sorting: results are sorted **by `Used` descending, then `Pattern` ascending (ordinal)** before display. Pinning this avoids the silent ordering churn flagged by the US-03 review.
- Grouping: when `state.Domain is null`, group by `step.Domain`; group order is **descending step count, then domain id ascending (ordinal)** for tie-breaks. Empty groups are omitted. When `state.Domain` is set, render a flat list.
- `PatternRenderer` parses `{...}` tokens (regex `\{([^}]*)\}`). Each token splits on `:` — `{name : type}` → name + type pill, `{type}` only → type pill with no name. Static text between tokens is passed through `HighlightRenderer`.
- `HighlightRenderer` splits text on case-insensitive ordinal matches of `state.Query` (trimmed; skipped if empty) and wraps matches in `<mark>`.
- `+` button: out-of-scope for v1 (US-09 wires it). Renders disabled with `aria-label="Add to scenario (coming soon)"` so the UI is present but the behaviour stub is explicit. Star button toggles favourite via `IFavouritesStore.Toggle`. Both call `e.StopPropagation()` so they don't trigger row selection.

**Tech stack additions:** none.

## Design notes

- **`StepList` sort key**: `OrderByDescending(s => s.Used).ThenBy(s => s.Pattern, StringComparer.Ordinal)`. Applied AFTER `FilterEngine.Apply` so the engine stays pure / ordering-agnostic.
- **List header**: shows `{filtered.Count} of {store.Steps.Count} matching` plus, when `state.Query` non-empty, ` for "{state.Query}"`. The "Sorted by most used" button is a static `<button>` element with `disabled` and a tooltip hint — present in markup, no behaviour. Don't pretend it does something it doesn't.
- **Type chip colour**: derive from a small static map in code (`Given→teal`, `When→amber`, `Then→violet`, `And→grey`) via CSS classes `chip-given`, `chip-when`, `chip-then`, `chip-and`. Avoid touching `DomainPalette` — that's for domain dots only.
- **Tags rendering**: show up to 3 tags joined by a thin separator (`·`); if there are more than 3, render `+N` chip at the end. Hidden when the step has no tags.
- **Empty state**: a single `.step-list-empty` card: `<p>No steps match your filters.</p>` plus a hint like `<p class="hint">Try clearing a filter or shortening your search.</p>`.
- **Scroll**: `.step-list-panel` (already defined for MainLayout flex region) gets `overflow-y: auto`. Header sticks via `position: sticky; top: 0;` inside the scroll container.
- **Selection styling**: selected row gets `is-selected` class; row click sets `selection.Selected = step`. Star and + buttons stop propagation. Until US-06 the detail panel renders nothing for the selection — that's fine; tests assert `SelectionState.Selected` after the click rather than DOM in the detail panel.

### Task 2 — `HighlightRenderer`
- [ ] Create `src/Delta.DocView.Client/Components/HighlightRenderer.razor`. Parameters: `Text` (string), `Query` (string?).
- [ ] If `Query` is null/whitespace, render the text verbatim.

### Task 3 — `PatternRenderer`
- [ ] Create `src/Delta.DocView.Client/Components/PatternRenderer.razor`. Parameters: `Pattern` (string), `Query` (string?).
- [ ] Parse `Pattern` with regex `\{([^}]*)\}`. For each token, split on `:` (trim each part):
    - Two parts: `<span class="param-pill param-{type}"><em class="param-name">{name}</em>:<span class="param-type">{type}</span></span>`
    - One part: `<span class="param-pill param-{type}"><span class="param-type">{type}</span></span>`
- [ ] Static text between tokens is rendered via `<HighlightRenderer Text="..." Query="@Query" />`.
- [ ] Tests in `tests/Delta.DocView.Tests/Components/PatternRendererTests.cs`:
    - Pattern with no tokens renders only the highlighted text.
    - `{string}` renders a single type-only pill.
    - `{user : string}` renders name + type pill.
    - Multiple tokens with interleaved text render in order.
    - Query that matches static text wraps in `<mark>` but does NOT cross into pill content.

### Task 4 — `StepRow`
- [ ] Create `src/Delta.DocView.Client/Components/StepRow.razor`. Parameters: `Step Step`, `string? Query`, `bool IsSelected`. Inject `IFavouritesStore Favs`, `SelectionState Selection`.
- [ ] Markup:

## Risk + open questions

| # | Question | Owner | Decision |
|---|----------|-------|----------|
| 1 | Pattern token form — is `{type}` or `{name : type}` canonical? | Engineering | Renderer accepts both; sample data uses `{type}`, US-06 spec implies `{name : type}` exists too. Both supported. |
| 2 | Should the sort button render at all if it's display-only? | Product | Yes — it sets expectation that sort options will exist; disabled state communicates "not yet". |
| 3 | Selection clear-on-empty — when filters reduce the list to zero, should the current selection clear? | UX | No. Selection is independent of visibility; it stays until the user picks another or US-06 adds a clear button. |
